# playbridge

음악 앱이 다른 친구끼리 노래 목록을 링크 하나로 주고받는 웹앱입니다.
보내는 사람이 곡 목록을 만들면 링크가 생기고, 받는 사람은 자기 음악 앱을 골라 곡을 바로 열 수 있습니다.

## 화면

- **민트 카드 · 곡 목록**: 보내기 화면에서는 목록 이름과 곡 목록을 입력하고, 받은 노래 화면에서는 곡을 골라 엽니다.
- **테라코타 카드 · 앱 경로**: `친구의 앱 → 내 앱` 경로를 보여 주고, 받는 앱을 바꿀 수 있습니다.
- **레코드판 열기 버튼**: 곡을 고르면 판이 돌고(글자는 고정), 누르면 고른 앱이 열립니다.
- **Apple Music은 페이지 안에서 듣기**: 아이폰은 `music.apple.com` 링크를 운영체제가 앱으로 넘겨서, 폰에서는 PC처럼 웹 화면을 볼 수 없었습니다. 그래서 Apple Music을 고르면 레코드판이 `듣기` 버튼이 되고, 누르면 앱으로 나가지 않고 페이지 안에 애플 공식 웹 플레이어가 뜹니다. 앱으로 가고 싶으면 플레이어 아래 `앱에서 열기`를 누릅니다.
- **다른 앱은 검색어 자동 복사**: 폰에서는 앱이 검색어 없이 열리는 경우가 많아, 곡을 누를 때 `가수 곡명`을 자동으로 복사합니다. 앱 검색창에 붙여넣기만 하면 됩니다. 기기의 "동작 줄이기" 설정을 켜면 회전하지 않습니다.
- **목록 정리**: 곡 오른쪽 `×`로 곡을 빼고, `목록 비우기`로 입력 칸과 링크의 목록을 한 번에 지웁니다. `내 앱 기억 지우기`로 기억한 앱을 초기화합니다.
- **홈 화면 앱**: 아이폰 사파리에서 공유 → `홈 화면에 추가`를 하면 레코드판 아이콘으로 앱처럼 열립니다.
- PC에서는 두 카드가 좌우로, 폰에서는 위아래로 배치됩니다.

## 사용 방법

1. `보내기`에서 한 줄에 한 곡씩 `가수 - 곡 제목` 형식으로 붙여넣습니다. (곡 제목만 적어도 됩니다.)
2. 내가 쓰는 앱을 고르고 `목록 만들기`를 누릅니다.
3. `링크 복사`로 친구에게 보냅니다.
4. 받는 사람은 링크를 열고 자기 음악 앱을 고른 뒤 곡을 누릅니다. 고른 앱은 브라우저에 기억됩니다.

## 파일 구성

| 파일 | 설명 |
|---|---|
| `index.html` | 화면 구조 |
| `style.css` | 디자인 |
| `app.js` | 동작(목록 만들기, 링크 읽기, 앱 고르기) |
| `favicon.svg` | 탭 아이콘 |
| `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` | 홈 화면 아이콘 |
| `manifest.webmanifest` | 홈 화면 앱 설정(이름, 전체 화면, 색) |
| `api/apple.js` | Apple Music 곡 링크와 웹 플레이어 주소를 찾아 주는 서버 함수 (Vercel) |
| `vercel.json` | 보안 헤더 설정 |

빌드 과정이 없는 정적 사이트이고, `api/` 폴더의 서버 함수 하나만 Vercel이 자동으로 실행합니다.

## 배포 (Vercel)

1. 이 폴더의 파일을 GitHub 저장소 최상단에 올립니다.
2. Vercel에서 `Add New → Project`로 저장소를 가져옵니다.
3. Framework Preset은 `Other`, Build Command와 Output Directory는 비워 둡니다.
4. `Deploy`를 누릅니다.

## 보안 설계

- **서버에 목록을 저장하지 않음**: 목록은 링크의 `#` 뒷부분에만 담깁니다. 이 부분은 서버로 전송되지 않습니다.
- **링크 데이터 검증**: 링크에서 읽은 값은 형식을 검사하고, 곡 200개·가수 100자·제목 150자·목록 이름 60자로 제한합니다. 잘못된 값은 버립니다.
- **XSS 방지**: 화면에 넣는 모든 글자는 이스케이프합니다.
- **링크 주소 고정**: 곡 링크는 정해진 앱별 https 주소 틀에 검색어만 인코딩해서 넣습니다.
- **보안 헤더(`vercel.json`)**: 같은 출처의 스크립트·스타일만 허용하는 CSP(페이지 안에 넣을 수 있는 외부 화면은 `embed.music.apple.com` 한 곳만 허용), 다른 사이트 안에 넣어 보여 주기 차단, MIME 추측 차단, 리퍼러 미전송, 카메라·마이크·위치 권한 차단.
- **서버 함수 보호(`api/apple.js`)**: 요청할 곳을 `itunes.apple.com` 한 곳으로 고정하고 리다이렉트를 거부해 SSRF를 막습니다. 검색어는 200자로 제한하고, 돌려주는 주소도 `https://music.apple.com/`으로 시작할 때만 내보내고, 웹 플레이어 주소는 정해진 형식(`embed.music.apple.com/나라/album/.../번호?i=곡번호`)일 때만 만듭니다. 브라우저도 받은 주소를 한 번 더 검사합니다. 4초가 넘으면 중단하고, 결과는 하루 동안 캐시해 외부 호출을 줄입니다.
- **로그인 정보 미수집**: 음악 앱 아이디·비밀번호를 받지 않습니다.

## 서버를 쓰지 않은 이유

목록을 서버(Supabase 등)에 저장하지 않고 링크 안에만 담기로 했습니다. 다른 과제에서 쓰는 무료 한도를 넘기지 않기 위해서이고, 저장하는 개인 데이터가 없어 관리할 보안 위험도 줄어듭니다. 대신 이미 보낸 링크는 나중에 지우거나 막을 수 없습니다.

## 한계

- Apple Music 외의 앱은 **검색 화면**으로 이동하며, 폰에서는 앱이 검색어 없이 열릴 수 있습니다(복사된 검색어를 붙여넣어 해결). 자동 재생이나 보관함 담기는 하지 않습니다.
- Apple Music 정확한 링크는 검색 첫 결과를 쓰므로 같은 제목의 다른 곡이 열릴 수 있습니다.
- Apple Music 웹 플레이어는 로그인하지 않으면 미리듣기만 될 수 있습니다(실제 기기 확인 필요).
- 웹 플레이어 iframe에는 애플 공식 코드대로 `allow-scripts`와 `allow-same-origin`을 함께 줍니다. 브라우저가 경고를 띄우지만, 플레이어가 다른 출처(애플)에서 열리므로 우리 페이지에 접근할 수 없습니다.
- 앱별 검색 주소가 폰·카카오톡에서 어떻게 열리는지는 실제 기기에서 확인이 필요합니다.
- 곡이 많으면 링크가 길어집니다. 목록을 나누도록 안내합니다.
- 곡을 빼면 내 화면의 링크만 바뀝니다. 이미 보낸 링크는 그대로이므로 새 링크를 다시 보내야 합니다.
- 홈 화면 앱은 사파리와 저장 공간이 달라, 기억한 앱을 한 번 더 골라야 할 수 있습니다.
- `캡처로 넣기`는 다음 버전에서 추가할 예정입니다.
